# Study Deck

支持导入题库的渐进式自学平台。题库以独立 JSON 文件提供，可按章节学习、搜索、收藏、记录进度，并在安装后离线使用。

## 本地运行

```bash
pnpm install
pnpm dev
```

质量检查：

```bash
pnpm check
pnpm exec playwright install chromium firefox webkit
pnpm test:e2e
```

## GitHub Pages

仓库内的 `deploy-pages.yml` 会在推送 `main` 后运行单元测试、构建并部署 `dist/`。首次使用时在仓库 Settings → Pages 中选择 **GitHub Actions** 作为 Source。

Vite 使用相对资源路径，应用使用 HashRouter，因此可部署到任意项目级 Pages 路径。Service Worker 缓存应用壳，IndexedDB 保存已安装题库与学习状态。

## 题库契约

公开契约位于 [`schema/question-pack.schema.json`](schema/question-pack.schema.json)。导入器会拒绝：

- 超过 25 MB 或无法解析的文件；
- 未知 Schema 版本、重复题号、无效章节引用；
- 题目数量与 manifest 不一致；
- 非 HTTP/HTTPS 的外部参考链接。

Schema v1 同时支持 PDF 抽取题和原创整理题。`sourcePages` 仅用于真实 PDF 页码，可以省略；提供时仍须为正整数起止页。非 PDF 题目不会显示 PDF 标签，原始内容区域使用通用文案。原题平台、题号和原题 HTTP/HTTPS URL 可明确记录在 `revision.references`，原创练习应在题干标明来源类型。不同题库使用独立 `pack.id`；升级时保持题号稳定即可保留对应学习进度。

`tools/pack_extractor.py` 和 `tools/build_pack.py` 是无内容的通用转换工具。源文档、抽取结果、修订层和最终包可保存在独立内容仓库，不受本仓库 MIT 许可覆盖。

PDF 转换按字形的纵向重叠与横向坐标重建行，用字体大小、代码区域和 Markdown 标记区分正文与代码，保留代码缩进、短行和中文注释。发布前通过 pypdf 独立核验所有题干及字段内容，未解决的字符或顺序差异会阻止写入题库。打包器要求成功审计与当前 raw 文件的 SHA-256 摘要相符，并要求源文档异常有明确校订层。

转换同时保留数学上下标，保护行内 C++ lambda/双下划线标识符，按可靠几何对应恢复图形项目符号，并为编号列表添加正确的段落边界。内容仓库可配置经过审核且仅改变空白的精确跨行修复；不使用猜测性规则自动拼接所有英文单词。升级已安装题库后才会使用新版抽取数据；原文对照提供包括拓展在内的全部五个字段。

转换工具的回归检查（需要 Python 环境安装 pdfplumber、pypdf 和 pytest）：

```powershell
python -X utf8 -m pytest tools -q
```

## 目标集合与闭卷练习

学习页中的“加入集合”可以把题目保存到本地命名集合。集合成员只保存 `collectionId + packId + questionId`，不复制题干和答案；同一道题可以加入多个集合，不同题库的同题号始终分开。主导航中的“学习记录”提供目标集合、到期复习和尝试历史，也能从记录打开对应题库的具体题目。

点击“开始闭卷尝试”会收起提示、答案、拓展和原文，创建一个空白回答。先写下自己的回答，再选择“回答正确”或“答错或不完整”；答错需要填写错因，实践证据可以记录链接、代码路径或文字。证据按普通文字显示，不执行其中的 HTML。若本次尝试中打开了辅助内容，会保留使用提示的标记，收起内容不会清除该标记。

这是个人自评记录，不使用模型或规则给答案自动打分，也不证明用户已经掌握。新增记录不会修改原有 `new / review / mastered`、收藏状态或题目内容的 `raw / reviewed / verified` 标记。

复习使用简单的 1 / 3 / 7 / 14 天间隔：连续独立正确的第 1、2、3、4 次分别使用这些间隔，之后保持 14 天；用过提示或者答错会重置为 1 天，独立正确的计数也从头开始。每次保存会根据该次尝试重新排期，提前练习同样计入自评次数；这不是经过效果验证的记忆模型。日期按尝试时设备的本地日历日计算，不按固定 24 小时相加；跨月、跨年和闰日保留正确的日历日期。设备时钟早于已有尝试时会提示校准，避免伪造新的练习时间。

IndexedDB `qd-study` 从 Dexie version 2 升级到 3，仅新增 `studyCollections`、`collectionMembers`、`recallAttempts`、`reviewSchedules` 四张表。原题包 `schemaVersion: 1`、题目 ID、旧复合主键和原状态含义不变；不会把以前点击过“已掌握”的题目自动生成学习证据或复习记录。

## 备份、卸载和版本往返

“导出全部进度”使用个人备份格式 `schemaVersion: 2`，同时包含原状态、集合、成员、尝试和复习安排。题包格式仍然是 v1，这两个版本号互不关联。导入会校验字段类型、真实日期、重复 ID、集合成员归属，以及复习安排是否能由对应的完整尝试历史重算；验证或合并冲突失败时整个事务回滚。

- 旧版个人备份 v1 仍可导入；旧版的“完全覆盖”只覆盖原收藏与学习状态，保留它没有记录的新表。
- 新版 v2 的“完全覆盖”替换全部个人记录，不覆盖已安装的题库内容。
- “按时间合并”按实际时间比较旧状态，按 ID 合并尝试历史，再从合并后的历史重算复习日期。它是追加式合并，不用备份中缺少的成员表示删除；同一尝试 ID 内容冲突、或不同 ID 的集合重名会拒绝合并，可使用完整备份覆盖或保留一份数据后重新整理集合。
- 可以在尚未安装题库时恢复合法个人记录；页面会显示“题目尚未安装”。同一 `packId + questionId` 以后重新安装时自动恢复关联，不会借用其他题库的同题号。
- 题库升级即使暂时移除了某个题号，也会保留该题的所有个人记录。回装含相同稳定 ID 的版本后，原记录重新可用。
- 界面默认删除题库但保留个人记录。只有程序显式调用 `removePack(packId, true)`，才清理该题库的旧状态、尝试、复习安排和所有集合中的对应成员；集合本身和其他题库的数据保留。

个人记录只保存在当前浏览器的本地数据库中，没有账号同步。清除站点数据前请导出备份；实践证据与回答也会进入该备份，分享文件前请自行检查内容。

针对本功能的检查命令：

```powershell
pnpm test
pnpm build
pnpm exec playwright test tests/learning.spec.ts --project=chromium --project=mobile-webkit --workers=1
```

单元测试覆盖 v2 数据库迁移、日历调度、提示与错误重置、同题多库、旧新备份恢复、重复/畸形输入、明确清理与默认保留，以及题包版本往返。浏览器测试覆盖实际填写尝试、提示标记、到期页面、未安装题库恢复和明确题目链接。个人学习成果需要用户自己完成练习后记录；测试通过不表示内容已完成独立审阅或用户已掌握。
